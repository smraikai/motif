# Playback latency, September 10, 2026

Motif 1.5.0 is installed in `/Applications/Motif.app`. Open at Login remained enabled. The complete local check suite passed, and the installed executable matches the signed build.

## Results

Each matrix contains three music videos, two repetitions, and three selection modes. Each cell reports the median followed by the slowest sample. There are six samples per mode. All 72 samples in these four playable matrices completed, with no detected stall in the following second.

| Build | Empty stream cache | Click 1 second after results | Fully prepared |
| --- | ---: | ---: | ---: |
| 1.4.1 with HLS compatibility correction | 7595 / 10072 ms | 7377 / 9797 ms | 492 / 583 ms |
| Unpacked extractor and preroll | 2560 / 4010 ms | 2077 / 2942 ms | 120 / 125 ms |
| Native resolver, fresh client per sample | 1314 / 12095 ms | 438 / 1386 ms | 142 / 144 ms |
| 1.5.0, persistent client | 552 / 1771 ms | 93 / 95 ms | 142 / 147 ms |

With the persistent client, 17 of 18 selections started in under one second. The exception was the first selection, which included HTTP client and public playback-context startup. All six early search clicks and all six fully prepared clicks were under one second. The final matrix used no extractor fallback.

The earlier fresh-client stress run includes a 12,095 ms cold outlier. Resolution accounted for 11,697 ms. Resolver-stage diagnostics were added afterward, so the exact fallback cause was not captured for that sample. Three diagnostic repeats of that track took 1,088 to 1,493 ms and used the native resolver. Subsecond playback is not guaranteed during client startup or a slow provider/fallback response.

## Initial failure

The user's original baseline run resolved `JCKBaJDRMw4` in 8,084 ms, then failed to start playback. A direct probe reproduced a valid HTTP 206 response and an AVPlayer item that never became ready. The audio-only HLS rendition of the same video played successfully.

The timing baseline above uses source from commit `6756fb3` and its original one-file extractor, with HLS selection applied by the benchmark. It is a compatibility-corrected timing reference. It does not replace or erase the original failed baseline report.

## Changes

- Resolve ordinary audio through YouTube's public VISIONOS playback API, retaining visitor context and the HTTP session in memory. Keep the pinned extractor for unsupported responses and live streams.
- Prefer audio-only HLS streams over direct fragmented M4A streams.
- Prepare two likely selections concurrently and retain paused, prerolled AVPlayers for handoff.
- Bundle the official unpacked yt-dlp distribution, avoiding Python-runtime extraction on every request.
- Record resolution stages, actual extractor invocations, native errors, buffering state, and playback-start timing.

## Method and limits

- Apple silicon Mac, macOS 27.0 build 26A428. Application volume was 15%.
- The endpoint is AVPlayer reporting playback with at least 20 ms of advancing media time, sampled every 5 ms. This is not an acoustic loopback measurement and does not subtract silence in the recording or measure device latency.
- Search results are supplied directly to the real PlayerStore. Search-query time is outside the metric. Mix requests return an empty list to avoid unrelated traffic.
- Each sample creates a new PlayerStore and empty stream cache. HTTP, extractor disk, and system media caches are not flushed. The shared-client run deliberately retains the client, matching the menu-bar app's lifetime.
- Fully prepared samples wait for resolution plus two seconds before selection. Early-click samples wait only one second after results appear.
- Six samples per mode characterize this session; they are too few to establish a production latency guarantee.

## Reproduce

```sh
./macos/benchmark-comparison.sh --session shared --runs 2 --modes cold,search-click-1s,prefetched
./macos/benchmark.sh --session fresh --runs 2 --modes cold,search-click-1s,prefetched
```

The comparison defaults to HLS on the original baseline and the native resolver on the current build. Use `--profile hls` to isolate the extractor/preroll changes, or `--profile standard` to reproduce each build's original selection policy.

Raw reports are ignored local files under `work/benchmarks/20260910T144439Z/`. The original failed run is under `work/benchmarks/20260910T143715Z/`. Additional diagnostics are under `work/benchmarks/diagnostic/`. Signed stream URLs were removed from diagnostic dumps.
